# Бэкенд Primcom: описание для заказчика

Дата актуализации: 2026-03-18

Этот файл описывает возможности backend-продукта простым деловым языком.
Файл обновляется после ключевых изменений в API, парсере, ботах и логике данных.

## Что умеет backend сейчас

### 1. Каталог авто из Китая

- Автоматически собирает карточки из внешних источников (guazi, che168, dongchedi).
- В рабочем контуре на сервере основной источник сейчас `guazi`.
- Для каждой карточки сохраняет цену, пробег, год, характеристики, ссылку на источник и фото.
- Отдает данные на сайт через API: список, фильтры и детальную страницу карточки.

### 2. Ручные карточки Китая, Японии и Кореи

- Есть отдельный менеджер-бот в Telegram для ручного добавления карточек Китая, Японии и Кореи.
- Бот поддерживает создание, редактирование, удаление и просмотр последних карточек.
- Для японских карточек поддерживается поле "оценка по аукционному листу".
- Все операции менеджера защищены API-ключом.
- Рабочая схема допускает размещение менеджер-бота на отдельном зарубежном сервере, при этом карточки сохраняются в основной production backend и сразу видны на сайте.

### 3. Мониторинг телеграм-контуров

- Добавлен отдельный monitor-бот для контроля рабочих Telegram-сервисов.
- Monitor-бот проверяет состояние `primcom_bot` и `primcom-lead-api` и сообщает только при аварии.
- Для ручной проверки состояния предусмотрена команда статуса.

### 4. Парсер и автоматическое обновление базы

- Парсер запускается по расписанию через systemd timer.
- Есть ручной запуск для ускоренного наполнения каталога.
- Поддерживается ограничение на количество новых карточек за запуск.
- Автоматическое удаление старых карточек после парсинга отключено по умолчанию (безопасный режим).
- Добавлен отдельный нейтральный daily-импорт для пополнения карточек Китая и Кореи из внешнего каталога. Он работает по лимитам, не публикует внешний URL в API и останавливается, если источник показывает anti-bot проверку.

### 5. Работа с фото и качество карточек

- Фото скачиваются и хранятся локально на сервере.
- Для guazi добавлена фильтрация служебных картинок (QR, иконки, логотипы, зеленый бренд-арт и т.д.).
- В публичную выдачу не попадают карточки без валидных изображений.
- Есть сервисный скрипт очистки пустых карточек.

### 6. Перевод и нормализация данных

- Китайские названия переводятся в процессе загрузки данных.
- Поддерживается перевод через proxy/OpenAI.
- Добавлены ретраи и увеличенные таймауты для стабильной работы при массовом парсинге.

### 7. API и эксплуатация

- Доступны служебные endpoint-ы для проверки состояния (`/health`) и контроля запусков скрейпера.
- Ведется журнал запусков и технические логи для диагностики.
- Есть отдельный endpoint для заявок с сайта (`/api/lead`).

## Ключевые изменения (для заказчика)

### 2026-06-07

- В менеджерский Telegram-бот добавлен рынок "Китай".
- Эффект: карточки авто из Китая можно добавлять, редактировать и удалять вручную так же, как карточки Японии и Кореи.

### 2026-06-07

- Добавлен новый контур автоматического пополнения карточек Китая и Кореи из внешнего каталога.
- Реальный адрес источника хранится только в настройках сервера, а не в коде проекта.
- Для таких карточек публичный API не показывает внешнюю ссылку-источник.
- Фото принудительно перекодируются в единый формат WebP без метаданных.
- Эффект: каталог можно снова пополнять автоматически, при этом старые карточки и кэш фронта не меняются.

### 2026-03-18

- Зафиксирована новая production-схема для manager-бота: он может работать на зарубежном сервере, а сохранять карточки в основной backend.
- Подготовлен отдельный monitor-бот для контроля `primcom_bot` и `primcom-lead-api`.
- Эффект: ручное добавление карточек стало устойчивее к проблемам доступа к Telegram API, а эксплуатация Telegram-контуров стала прозрачнее.

### 2026-02-24

- Подготовлено единое описание backend-возможностей для заказчика в понятном формате.
- Зафиксировано правило: после каждого ключевого изменения backend этот файл обновляется.
- Эффект: текущий статус системы можно быстро согласовать без погружения в код.

### 2026-02-23

- Расширено управление ручными карточками Японии/Кореи.
- Добавлены операции просмотра, редактирования и удаления, плюс поле "оценка по аукционному листу" для Японии.
- Эффект: менеджер может полноценно вести карточки без ручных правок в БД.

### 2026-04-26

- Добавлена проверка содержимого фото guazi: служебные зеленые картинки Guazi отбрасываются даже если пришли как обычные CDN-файлы.
- Добавлен сервисный скрипт очистки уже сохраненных служебных Guazi-картинок.
- Эффект: в карточках должны оставаться фото автомобилей, а не графика источника.

### 2026-02-22

- Усилен контроль качества фото и фильтрация нерелевантных изображений в guazi.
- Каталог защищен от пустых карточек, добавлен скрипт сервисной очистки.
- Эффект: на сайте меньше карточек с пустыми или "левыми" фото.

### 2026-02-22

- Повышена устойчивость массового парсинга и перевода (ретраи, новые таймауты, fallback-механики).
- Эффект: меньше срывов загрузки и выше процент корректно заполненных карточек.

### 2026-02-22

- Автоудаление карточек после парсинга отключено по умолчанию.
- Эффект: снижены риски случайной потери данных при обновлениях парсера.

## Как обновлять этот файл

После каждого важного изменения добавить короткий блок в раздел "Ключевые изменения":

- что именно изменили;
- зачем это сделано;
- какой эффект для бизнеса или менеджера;
- нужно ли действие со стороны заказчика.
