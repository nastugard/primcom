# Manager Listings Bot (China/Korea/Japan)

Отдельный Telegram-бот для менеджера. Собирает данные карточки в диалоге и отправляет в backend:
`POST /api/manager/manual-listing`.

Этот бот НЕ связан со старым `telegram-bot_clean_2026-01-23`.

## Импорт публикации из Telegram

Менеджер может переслать боту готовую публикацию из Telegram-канала вместе с альбомом фотографий.

Бот:

- объединяет сообщения одного Telegram-альбома;
- извлекает из подписи рынок, марку, модель, год, пробег, двигатель, привод, кузов, мощность, комплектацию, оценку и цену;
- сохраняет все фотографии альбома в исходном порядке;
- не запрашивает отсутствующие характеристики и оставляет их пустыми;
- показывает стандартное подтверждение перед отправкой карточки на сайт.

Для запуска нажимать отдельную команду не нужно — достаточно переслать публикацию, когда бот не находится в другом диалоге. Кнопка `Импорт из Telegram` показывает эту подсказку.

Парсер находится внутри `main.py`, поэтому для выката функциональности достаточно обновить один файл.

## SEO-публикация

После успешного создания, изменения или удаления карточки backend возвращает:

- `seo_status`: `published`, `updated` или `catalog_only`;
- `seo_url`: модельная страница;
- `seo_reason`: причина, по которой SEO-страница не обновилась.

Бот показывает этот результат менеджеру. Для SEO-публикации обязательны страна, марка, модель, год, цена и хотя бы одно фото. Сам бот не создаёт тексты и не набивает страницу ключевыми фразами: статические страницы и полезные ссылки формирует проверяемый SEO-публикатор на backend-сервере.

## Что бот собирает
- площадка (Китай/Корея/Япония)
- марка
- модель
- год
- привод
- объем двигателя
- л.с.
- кузов (кнопками: седан/универсал/хэтчбек/купе/джип/кроссовер)
- комплектация (можно пропустить)
- оценка по аукционному листу (для Японии, можно пропустить)
- цена
- фото (минимум 1; обычные Telegram-фото или файлы-изображения JPG/PNG/WEBP)

## Быстрый запуск локально

```bash
cd manager-listings-bot
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# заполните BOT_TOKEN / MANAGER_API_KEY / MANAGER_ALLOWED_IDS
python main.py
```

## Команды в Telegram
- `/new` — новая карточка
- `/edit [UUID]` — изменить карточку
- `/delete [UUID]` — удалить карточку
- `/recent [china|korea|japan]` — последние карточки с ID
- `/cancel` — отменить текущий диалог

## Кнопки меню в боте
- `Добавить карточку`
- `Изменить карточку`
- `Удалить карточку`
- `Показать последние карточки`
- `Импорт из Telegram`

Меню показывается после `/start`, после успешного сохранения/удаления и после отмены диалога.

## Безопасность
- В `.env` задайте `MANAGER_ALLOWED_IDS` (список user_id через запятую).
- На backend в `.env` должен быть тот же `MANAGER_API_KEY`, который бот шлет в `X-Manager-Api-Key`.

## Production заметки
- Бот можно держать на отдельном сервере от backend. Достаточно, чтобы у него был доступ к Telegram API и корректный `API_BASE_URL` до production backend.
- Рабочая схема на март 2026: `manager-listings-bot` вынесен на зарубежный сервер, а карточки сохраняются в production backend `api.primcom.ru`, который уже отдает их сайту.
- Одновременно должен работать только один экземпляр этого бота с одним `BOT_TOKEN`. Перед переносом на новый сервер старый экземпляр нужно остановить.
- Если в чате появляется `Ошибка отправки: TimeoutError...`, это обычно проблема доступа сервера бота к Telegram API или скачиванию фото из Telegram.
- Текущая версия с выводом статуса SEO-публикации: `2026-08-14.seo-publish-v1`.
