# SEO-конвейер Primcom

Источник контента: `seo/content-registry.json`.

## Выпуск страниц

```bash
node scripts/generate-seo-pages.mjs
node scripts/check-seo-pages.mjs
```

Автоматическая синхронизация с ручными карточками Telegram-бота:

```bash
node scripts/publish-seo-catalog.mjs
```

Публикатор получает только карточки с `source_listing_id` вида `mgr-{country}-...`, группирует их по стране/марке/модели, проверяет обязательные поля, собирает страницы во временной папке, запускает QA и только затем атомарно заменяет `cars/`, `guides/`, `sitemap.xml` и реестр. Для отдельного document root задаётся `PRIMCOM_SITE_ROOT`.

Генератор создаёт готовые статические страницы в `cars/` и `guides/`, очищает устаревшие сгенерированные разделы и обновляет `sitemap.xml`.

## Защита от массовой деиндексации

`sync-seo-catalog.mjs` прерывает синхронизацию, если каталог API вернул подозрительно мало карточек:

- у страны были активные модели, а стало ноль;
- общее число активных моделей упало ниже `SEO_MIN_ACTIVE_RATIO` (по умолчанию `0.5`) от предыдущего реестра.

Проверка нужна потому, что успешный ответ API с пустым `items` формально корректен, но переводит все модели в `inactive`, то есть в `noindex,follow` и вне sitemap. Порог `expected at least 20 generated URLs` в QA такой случай не ловит: снятые с публикации страницы всё равно генерируются.

При срабатывании защиты сборка падает, рабочие `cars/`, `guides/`, `sitemap.xml` и реестр не заменяются, а менеджер видит в боте неуспешный SEO-статус. Намеренное сокращение каталога выполняется вручную с `SEO_ALLOW_CATALOG_SHRINK=1`.

## Правила публикации

- В индекс и sitemap попадает только контент, утверждённый реестром.
- Кейсы и экспертные FAQ остаются только в рабочем реестре, пока нет подтверждённых фактов и ручной проверки; публичные заглушки не создаются.
- Цены модельных страниц отражают данные каталога на указанную дату, но не являются офертой или итоговой стоимостью под ключ.
- Для автоматической публикации обязательны страна, марка, модель, год, положительная цена и хотя бы одно фото.
- После удаления последней карточки модельная страница сохраняется с `noindex,follow` и исключается из sitemap.
- Массовое снятие моделей с публикации не выполняется автоматически: нужен ручной запуск с `SEO_ALLOW_CATALOG_SHRINK=1`.
- SEO-плитки являются видимыми раскрывающимися навигационными блоками и содержат только ссылки на существующие полезные страницы.
- После изменения данных обязательно повторно запускать генератор и QA.
- Нельзя добавлять вымышленные отзывы, кейсы, характеристики или сроки.

## Ручная проверка перед релизом

1. Сверить выбранные предложения с production API.
2. Подтвердить коммерческие формулировки и актуальность цен.
3. Проверить страницы на mobile и desktop.
4. После публикации проверить индексирование в Яндекс.Вебмастере и Google Search Console.
