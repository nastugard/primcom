# SEO-конвейер Primcom

Актуализировано 22.10.2026. Локальный QA: 152 генерируемые индексируемые страницы / 163 URL sitemap. Тесты формы (12/12), публикатора и локальной доставки пройдены повторно. Публикация органического релиза подтверждена сохранённой проверкой от 18.10.2026; обновление серверного публикатора и последующей мобильной шапки не подтверждено. См. [статус внедрения](research/2026-10-18-organic-growth/IMPLEMENTATION-STATUS.md) и [порядок выката](../DEPLOY_REGRU.md).

Источник контента: `seo/content-registry.json`.

## Выпуск страниц

```bash
node scripts/generate-seo-pages.mjs
node scripts/check-seo-pages.mjs
```

Автоматическая синхронизация с ручными карточками Telegram-бота:

```bash
node scripts/publish-seo-catalog.mjs
```

Публикатор получает только карточки с `source_listing_id` вида `mgr-{country}-...`, группирует их по стране/марке/модели, проверяет обязательные поля, собирает страницы во временной папке, запускает QA и только затем атомарно заменяет `cars/`, `guides/`, `sitemap.xml` и реестр. Для отдельного document root задаётся `PRIMCOM_SITE_ROOT`.

Генератор создаёт готовые статические страницы в `cars/` и `guides/`, очищает устаревшие сгенерированные разделы и обновляет `sitemap.xml`.

## Автопубликация

Карточка из бота может попадать на сайт без ручной пересборки: см. `seo/AUTOPUBLISH.md`.
Команда `scripts/publish-and-sync.mjs` собирает страницы, проверяет их и отправляет на
хостинг только изменившиеся файлы.

Даты честные: `lastmod` в sitemap и надпись «Данные обновлены» меняются, только когда
изменилась сама страница. Состояние хранится в `seo/lastmod-state.json`.

## Защита от массовой деиндексации

`sync-seo-catalog.mjs` прерывает синхронизацию, если каталог API вернул подозрительно мало карточек:

- у страны были активные модели, а стало ноль;
- общее число активных моделей упало ниже `SEO_MIN_ACTIVE_RATIO` (по умолчанию `0.5`) от предыдущего реестра.

Проверка нужна потому, что успешный ответ API с пустым `items` формально корректен, но переводит все модели в `inactive`, то есть в `noindex,follow` и вне sitemap. Порог `expected at least 20 generated URLs` в QA такой случай не ловит: снятые с публикации страницы всё равно генерируются.

При срабатывании защиты сборка падает, рабочие `cars/`, `guides/`, `sitemap.xml` и реестр не заменяются, а менеджер видит в боте неуспешный SEO-статус. Намеренное сокращение каталога выполняется вручную с `SEO_ALLOW_CATALOG_SHRINK=1`.


## Таблицы таможенных ставок

Страница `pages/rastamozhka-i-poshliny.html` содержит статические таблицы ставок между
маркерами `<!-- customs-rates:start -->` и `<!-- customs-rates:end -->`.

Числа не редактируются руками. Источник истины —
`china_cars_backend/app/services/import_calculator/config.py`, тот же конфиг,
по которому считает боевой калькулятор. Примеры расчёта считаются его же функциями.

```bash
python3 scripts/build-customs-tables.py          # пересобрать блок
python3 scripts/build-customs-tables.py --check   # упасть, если страница отстала от config.py
```

После любого изменения ставок в `config.py` обязательно выполнить пересборку,
иначе сайт будет публиковать устаревшие ставки. Страница не генерируется
`generate-seo-pages.mjs`, поэтому автопубликация её не перезаписывает.

## Правила публикации

- В индекс и sitemap попадает только контент, утверждённый реестром.
- Кейсы и экспертные FAQ остаются только в рабочем реестре, пока нет подтверждённых фактов и ручной проверки; публичные заглушки не создаются.
- Цены модельных страниц указаны под ключ на дату объявления. Наличие, состав расходов, город выдачи и актуальная цена подтверждаются менеджером; опубликованная сумма не является офертой. Таможню и доставку не прибавляют к ней повторно.
- Для автоматической публикации обязательны страна, марка, модель, год, положительная цена и хотя бы одно фото.
- После удаления последней карточки модельная страница сохраняется с `noindex,follow` и исключается из sitemap.
- Массовое снятие моделей с публикации не выполняется автоматически: нужен ручной запуск с `SEO_ALLOW_CATALOG_SHRINK=1`.
- SEO-плитки являются видимыми раскрывающимися навигационными блоками и содержат только ссылки на существующие полезные страницы.
- После изменения данных обязательно повторно запускать генератор и QA.
- Нельзя добавлять вымышленные отзывы, кейсы, характеристики или сроки.

## Ручная проверка перед релизом

1. Сверить выбранные предложения с production API.
2. Подтвердить коммерческие формулировки и актуальность цен.
3. Проверить страницы на mobile и desktop.
4. После публикации проверить индексирование в Яндекс.Вебмастере и Google Search Console.

## Органический каталог (18.10.2026)

`seo/organic-content.json` — редакционные тексты трёх подборок, пяти моделей и факты трёх примеров. Генератор создаёт подборки и примеры внутри `cars/`, поэтому они входят в существующую атомарную публикацию и синхронизацию. Примеры — разборы объявлений, не вымышленные кейсы завершённого привоза.

На подборках используются отдельные подходящие объявления, а не минимальная цена модели вообще. Мощность без значения не попадает в фильтр до 160 л.с.; минивэны отбираются по явному типу кузова. Подборка без подходящих объявлений получает noindex и исключается из sitemap.

Генератор включает `components/lead-modal.html` и `components/cookie-notice.html` в HTML всех создаваемых страниц. Эти файлы и `organic-content.json` обязательны в серверном пакете публикатора. При ручной сборке lastmod сохраняется в `seo/lastmod-state.json`, при staging — в каталоге результата.

Проверки:

```bash
node scripts/check-seo-pages.mjs
node scripts/test-seo-publisher.mjs
node scripts/test-organic-conversion.mjs
```

Повторная сборка с неизменными данными не меняет даты sitemap. Общая дата изменения данных модели не заменяет дату объявления или проверку цены.
